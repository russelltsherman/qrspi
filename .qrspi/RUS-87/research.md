## Discovered Patterns

- **One-shot, stdlib-only Python scripts.** Every command is a standalone
  `scripts/<name>.py` with its own `argparse` parser, a `main(argv=None)`
  entrypoint, and `sys.exit(main())`. No daemons, no long-lived processes, no
  packaging manifest, no unified `qrspi` binary. (`scripts/qrspi_config.py`,
  `scripts/qrspi_metrics_append.py`, `scripts/qrspi_critic_metrics.py`.)
- **stdout = JSON envelope, stderr = prose, exit code = result.** Machine output
  is a single `{ok, ...}` JSON object on stdout; diagnostics go to stderr;
  success is the exit code + `ok` flag. The JS side JS-parses stdout
  (`parseConfigEnvelope`, `.claude/workflows/qrspi-batch.js:362`).
- **Pure core / IO shell separation for testability.** Pure functions
  (`select_value`, `build_record`, `wrap_envelope`) take all inputs (including
  time and paths) as arguments and do no IO, so the `_test.py` sibling exercises
  them with in-memory values; IO/subprocess lives only in `main()`.
  (`scripts/qrspi_config.py:36-42`, `scripts/qrspi_critic_metrics.py:54-105`.)
- **Self-locating root, never cwd.** Scripts derive the repo root from `__file__`
  or `qrspi_paths.resolve_repo_root` (git-common-dir first, to avoid worktree
  double-nesting), never from cwd. (`scripts/qrspi_config.py:29`,
  `scripts/qrspi_metrics_append.py:48-55,131`.)
- **Append-and-verify-non-empty, fail-closed writes.** JSONL writers append one
  `\n`-terminated JSON object and verify the file is non-empty, returning an
  error otherwise. (`scripts/qrspi_metrics_append.py:82-99`.)
- **camelCase JSONL field convention.** Existing JSONL (`critic-metrics.jsonl`)
  uses camelCase keys (`ticketId`, `runId`, `terminalAction`, `findingsCount`) —
  NOT the snake_case the questions assume.
- **Durable cross-run counters live as git head-commit trailers**, with explicit
  read-side and writer-side resets — the repo's only "state that survives a
  one-shot run." (`CI-Revise-Attempt`, `.claude/workflows/qrspi-batch.js:975`,
  `scripts/qrspi_ci_revise_bump.py`.)
- **Closed-enum, fail-closed dispatch.** The single dispatch site is a JS
  `switch` on `decision.action` against a closed `Set`; an unknown action is a
  hard error. No dynamic handler registry exists.
  (`.claude/workflows/qrspi-batch.js:211-213,1644-1656,251-252`.)
- **Nested config gets a dedicated reader.** The general reader
  (`qrspi_config.py`) is single-top-level-key, string-valued; nested config
  (`critics.design.maxRounds`) has its own reader (`qrspi_critics_config.py`) —
  the precedent is a purpose-built reader per nested namespace, not extending the
  single-key one. (`.qrspi/config.example.json`, `scripts/qrspi_critics_config.py`.)
- **`scripts/*_test.py` + `run_tests.py` is the whole test story.** Subprocess-
  per-file unittest, no pytest, CI-gated. Time and paths are injected as args,
  never mocked from a clock; filesystem tests use `tempfile.TemporaryDirectory`.
