## Current State

The resume capability this ticket locks in already exists in code; it is simply under-tested as a *resume* contract and undocumented as a guarantee.

Planning-phase done-ness is decided deterministically by `detect_existing(qrspi_dir)`, which iterates the six-name `ARTIFACTS` list and maps each `<qrspi_dir>/<name>.md` to `os.path.getsize(path) > 0`, treating any `OSError` (missing file/dir) as `False` and never reading file contents (ref: Q1). A zero-byte artifact and a missing artifact both yield `False`, so a truncated/aborted write correctly reads as recompute rather than a false skip — the safe direction (ref: Q8). This map is surfaced on the resolver envelope's `existing` field; skippability is encoded purely as `existing[<phase>] == true`, with no separate skip flag, and the error path forces all-`False` (ref: Q7).

The orchestrator consumes that map as `r.existing` and passes it into `runPhase`, whose first action is `if (existing && existing[name]) { log('reusing existing'); return true }` — skipping the producer agent, node-check, critic loop, and persist for any already-persisted phase (ref: Q2). `persistArtifact` is the single, final success gate: within `runPhase` it runs only after the producer and all critic/node-check stages pass, shelling to `qrspi_persist.py`, which refuses to move a zero-byte staged file and re-verifies the destination is non-empty after `shutil.move` (ref: Q3). Because the producer writes to a token-free staging path and persist is the gate, a mid-phase `agent()` returning the `null` failure sentinel never reaches persist, so no half-written canonical artifact exists; on re-run `detect_existing` reports `False` and the phase recomputes (ref: Q9).

Slice done-ness is decided differently — by branch naming. `slice_numbers(branch_lines)` regex-matches `/slice-(\d+)$` and returns a sorted, de-duplicated ascending int list; `slice_branches(branches, ticket)` formats those into ascending `<ticket>/slice-<n>` names (ref: Q4). Both are gap-agnostic: a `{slice-1, slice-3}` set returns exactly `[1, 3]` with no synthesized "next" slice, and `pick_tip` returns `max(snums)`, the highest present number (ref: Q10). Which slice runs next is decided downstream by the setup agent's per-slice `alreadyCommitted` flag, not by these pure helpers (ref: Q6, Q10).

Tests live in `scripts/qrspi_resolve_test.py` — stdlib-only, assert-based via a `check(name, got, want)` harness, exiting non-zero on any failure (ref: Q5). The existing `detect_existing` test seeds a bare `tempfile.TemporaryDirectory()` with non-empty and zero-byte files and asserts the boolean map (ref: Q5, Q11). `run_tests.py` auto-discovers every `scripts/*_test.py` and runs each as an exit-coded subprocess; `.github/workflows/tests.yml` invokes `python3 scripts/run_tests.py` as the CI gate on every PR and push to `main` (ref: Q12). `docs/testing-dynamic-workflows.md` currently says nothing about resume/skip semantics — it documents only the Functional-Core/Imperative-Shell testing thesis and why `qrspi-batch.js` is not unit-testable (ref: Q14). The probe `probe-agent-failure.js` referenced by the ticket does not exist within this worktree's scope; it exists only as an untracked file in the main checkout, outside the research firewall (ref: Q13).

## Desired End State

**Structural honesty — the deterministic surface stops one step short of the guarantee, by necessity.** Across AC2 and AC3, every behavior that actually *constitutes* the resume guarantee — a phase being skipped, only the next slice being re-entered — lives in the harness-coupled JS/LLM layer and is **inspection-only**: phase-skip is the JS `runPhase` early-return, and per-slice skip is the setup agent's non-deterministic `alreadyCommitted` flag. The Python unit tests assert the **pure helpers that feed those decisions** (`detect_existing`, `slice_branches`/`pick_tip`, and the `build_envelope` passthrough), **not the decisions themselves**. So although the ticket asks for the guarantee to be "asserted, not just claimed," the deterministic test surface can only assert the inputs to the guarantee, never the guarantee's behavior — that final step is unit-testable only by refactoring `qrspi-batch.js` (explicitly out of scope). This is stated once here as the unifying frame; the per-AC and Risk-Register entries below are instances of it.

Every acceptance criterion maps to a concrete behavior below.

- **AC1 — Resume semantics are unit-tested. ALREADY MET — no net-new work.** The existing `detect_existing` block (`scripts/qrspi_resolve_test.py:68–84`) already asserts the full resume contract: present non-empty → `True` (skipped), missing → `False`, and present-but-empty zero-byte → `False` (recomputed). The zero-byte case (`:82`) is the load-bearing assertion proving a truncated write triggers recompute, not a false skip (ref: Q1, Q8). Acceptance is satisfied by the existing tests; the only optional addition is resume-framing comments on that block (not a new assertion).
- **AC2 — Slice-boundary resume is unit-tested. ALREADY MET except ONE assertion.** `slice_branches` and `pick_tip` (both already imported) are already asserted for the ascending set and tip, including non-contiguous/out-of-order cases for `pick_tip` (`:99–101`). The **single** net-new assertion is a **non-contiguous `slice_branches` case** (e.g. `{slice-1, slice-3}` → `["RUS-1/slice-1", "RUS-1/slice-3"]`), the one combination currently unasserted (ref: Q4, Q10). These transitively exercise `slice_numbers`; a direct `slice_numbers` assertion adds nothing and is dropped (see Decision 1).
- **AC3 — A re-run does not recompute persisted upstream phases. NET-NEW, but inspection-bound.** **No deterministic test can assert AC3's behavioral contract**, because the skip decision is not in Python — it lives entirely in the JS `runPhase` early-return (`if (existing && existing[name]) return true`). The Python surface stops one step short: `build_envelope` takes both `existing` and `decision` as inputs and stores `existing` **verbatim** with no derivation (`scripts/qrspi_resolve.py:225  env = { … "existing": existing, "decision": decision, … }`) — it does not "mark" anything skippable. The honest net-new AC3 deliverable is therefore a thin **passthrough** assertion: seed a `<tmp>/.qrspi/<ticket>/` layout, build the `existing` map from it, and assert `build_envelope(…, existing=that_map)["existing"] == that_map` — i.e. that `build_envelope` carries the `existing` map onto the envelope's `existing` field. The JS skip causation (`runPhase`'s early-return consuming that map) is **inspection-only — not unit-tested** (ref: Q2, Q11). This is explicitly **not** "asserts the skip-map marks phases skippable"; it is a passthrough identity check plus the AC1-covered `detect_existing` map production feeding it.
- **AC4 — The guarantee is documented.** `docs/testing-dynamic-workflows.md` gains a section stating: resume is phase- and slice-boundary by design; a mid-phase/mid-slice `agent()` `null` correctly recomputes that unit because `persistArtifact` is the post-validation gate; and no signature-based classifier exists because the seam yields a bare `null` (ref: Q3, Q9, Q14).
- **AC5 — Probe is committed or its result captured.** The probe result is captured verbatim in this design doc (see Probe Evidence below), since the probe artifact is out of scope for the worktree (ref: Q13); committing the file is the alternative if a human prefers.
- **AC6 — Both run under `run_tests.py` and CI; suite stays green.** New tests are added as `scripts/*_test.py`, auto-discovered with zero config and run by the existing CI gate (ref: Q12).

## Pattern Decisions

### Decision 1: New sibling test file vs extend the existing resolver test

| Option | Approach | Pros | Cons |
|--------|----------|------|------|
| A | Add cases to `scripts/qrspi_resolve_test.py` | Reuses the existing `check()` harness and imports; sits beside the precedent `detect_existing` fixture; one file to read for resume contract | Grows an already-multi-purpose file |
| B | New `scripts/qrspi_resume_test.py` sibling | Resume contract isolated by name; signals intent | Duplicates the `check()`/import boilerplate; splits resolver-helper coverage across two files |

**Recommendation:** Option A.
**Rationale:** The helpers `detect_existing`, `slice_branches`, `pick_tip`, `build_envelope`, and `ARTIFACTS` are all already imported in `qrspi_resolve_test.py` (ref: Q5), and the existing fixtures are the exact pattern the net-new assertions extend (ref: Q5, Q11). Every helper the net-new work touches is therefore already on the import surface — **no new import is needed.** (No direct `slice_numbers` assertion is added — `slice_branches`/`pick_tip` already cover it transitively, ref: Q4.) `run_tests.py` auto-discovers either layout (ref: Q12), so there is no discovery benefit to a new file. Co-location keeps the resume contract next to the helpers it constrains.
**NEW PATTERN?** No — extends the established stdlib `check()`-harness convention using only already-imported helpers; no new imports.

### Decision 2: What the AC3 skip-map test actually targets

| Option | Approach | Pros | Cons |
|--------|----------|------|------|
| A | Seed `os.makedirs(<tmp>/.qrspi/<ticket>)`, build the `existing` map, assert it via `detect_existing` on the nested path | Reproduces the call-site layout | Behaviorally identical to the existing bare-dir `detect_existing` test (`:72`): `detect_existing(qrspi_dir)` is pure over whatever path it receives, and `os.path.getsize` is indifferent to nesting depth, so the deeper path adds **no coverage** — and the `os.path.join(worktree, ".qrspi", ticket)` join lives in the **caller** (`qrspi_resolve.py:393`), not in the function under test, so it stays untested either way. This re-tests `detect_existing`, which AC1 already covers (`:68–84`). |
| B | Seed the layout, build the `existing` map for it, and assert via **`build_envelope`** that the map is carried verbatim onto the envelope's `existing` field (a passthrough identity check) | Asserts the only Python-side behavior there is to assert — that `build_envelope` propagates `existing` onto the contract — against the already-pure, already-tested `build_envelope` (`:115+`); does **not** re-test `detect_existing`, and does **not** overclaim a behavioral skip assertion | Thin: a dict-passthrough identity check, not a behavioral skip proof (which is structurally impossible in Python — see below) |

**Recommendation:** Option B — **with no overclaim about what it proves.**
**Rationale:** **No deterministic Python test can assert AC3's behavioral contract** ("a re-run does not recompute persisted upstream phases"), because the skip decision is not in Python: it is the JS `runPhase` early-return (`if (existing && existing[name]) return true`). `build_envelope` takes both `existing` and `decision` as inputs and stores `existing` **verbatim** with no derivation (`scripts/qrspi_resolve.py:225  env = { … "existing": existing, "decision": decision, … }`) — nothing in it "marks" anything skippable. So the Option-B assertion reduces to (a) `detect_existing(seeded_dir)` producing the right map — which is AC1, already covered — plus (b) `build_envelope(…, existing=that_map)["existing"] == that_map`, a dict-passthrough identity check. **Neither asserts AC3's behavioral contract.** Calling this "asserts the skip-map marks phases skippable" would be the same species of overclaim the prior review caught in Option B's first rationale ("mirrors the real call-site join") and withdrew; that earlier framing was wrong and is withdrawn here too. Option A is rejected because it only restates the existing bare-dir `detect_existing` test (`:72`) — `detect_existing` is pure over any path and `os.path.getsize` ignores nesting depth, so a deeper temp path buys cosmetic fidelity, not coverage; and the `os.path.join(worktree, ".qrspi", ticket)` join is in the **caller** (`qrspi_resolve.py:393`), not the function under test, so it is untested under either option. Option B is chosen only because the passthrough is the single real (if thin) Python behavior on the AC3 path; the actual skip causation is JS `runPhase`, **inspection-only, not unit-tested**, and labeled as such — honoring the ticket's "no false promise of a `qrspi-batch.js` unit test" (ref: Q2, Q11).
**NEW PATTERN?** No — same `tempfile`/`check()` pattern against the already-imported `build_envelope` (ref: Q11).

## Probe Evidence (transcribed from the ticket's Context section per AC5)

**Provenance note:** the probe file `probe-agent-failure.js` is outside the research-firewall scope (Q13), so the result below was **not** captured from a probe run/read in this worktree — it is **transcribed from the ticket's Context section**, which reported the run. It satisfies AC5 ("committed or its result captured") as a faithful transcription, not as a first-hand probe capture; committing the file (OQ1) is the alternative path to first-hand evidence in-repo.

The probe `probe-agent-failure.js` (run 2026-06-14, per the ticket's Context) induced an API/network-layer failure via an invalid model id (a 4xx — same layer as the targeted 429/529/`ECONNRESET`/`fetch failed`/stream `terminated` classes). Result: the `agent()` seam returns a **bare `null` with the error message discarded**; only client-side config validation (unknown `agentType`) throws a catchable message, and a transient network fault never reaches that path. This is corroborated by in-scope code: every `agent()` caller treats `null` as the failure sentinel and logs only a generic message with no error text (ref: Q9, Q13). With only `null` visible, a signature classifier has no input — so the classifier, allowlist, default-deny matching, and backoff are unbuildable here and are withdrawn. The probe file itself is not present within the research-firewall scope (ref: Q13); a human may commit it for permanence.
