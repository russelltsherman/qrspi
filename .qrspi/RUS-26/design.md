# Design — Create a new agent skill called writing Product Requirements Documents

**Ticket:** RUS-26
**Research basis:** research.md @ 2026-05-31
**Generated:** 2026-05-31T00:00:00Z
**Status:** draft

## Current State

The repo holds ten skills under `.claude/skills/<name>/SKILL.md`; eight are thin wrappers (25-35 lines) that spawn a companion `.claude/agents/qrspi-<phase>.md` agent, while two (`qrspi-ticket`, `qrspi-work`) are self-contained and hold their full procedure inline (ref: Q1, ref: Discovered Patterns). There is no PRD-authoring skill today and no general document-authoring skill (ref: Q1). Only `qrspi-work` externalizes content into a `references/` subdirectory; no skill uses `scripts/` or `assets/` (ref: Q1, ref: Inconsistencies). Skill frontmatter consistently carries `name`, `description`, `command`, `argument-hint`, and `allowed-tools`, with the directory name equal to `name` equal to the `/command` (ref: Q3, ref: Q4). Skill-specific templates are stored either as inline fenced blocks in the body (`qrspi-ticket`) or, for overflow, as a file under the skill's own directory; QRSPI pipeline artifact templates live separately in `.qrspi/templates/` and are reference-only (ref: Q6). The conditional-questioning gate pattern already exists in `qrspi-ticket`, which restates understanding, asks at most two questions at a time, continues until fields are sufficient, and self-reviews to strip solution leakage (ref: Q8). The "problem before solution" separation is a house value baked into the whole pipeline (ref: Discovered Patterns). Quality is verified behaviorally through weighted assertions in `evals/suite.json` graded by `scripts/grade.py` (which already provides `output_file_exists`, `has_section`, `line_count`, `no_solution_language`) and run via `run_loop.sh`/`scripts/run_eval.py`, not by any frontmatter lint or registration step (ref: Q7, ref: Q10, ref: Q12). The Anthropic "skill builder" (skill-creator) referenced by the ticket is NOT in the repo — it is an external/global skill outside `REPO_ROOT`, referenced once in `.claude/agents/qrspi-structure.md`; its file-output contract and its own eval loop cannot be confirmed from repo facts (ref: Q2, ref: Q11, ref: Inconsistencies).

## Desired End State

A new self-contained skill at `.claude/skills/writing-prds/SKILL.md` exists and is discoverable via its `/command` and description. Mapping each acceptance criterion to behavior:

- *agentskills.io directory structure with valid frontmatter* → skill dir `writing-prds/` with `SKILL.md` carrying valid YAML frontmatter (`name`, `description`, `command`, `argument-hint`, `allowed-tools`) matching repo conventions (ref: Q3).
- *Built using the Anthropic skill builder skill* → the skill is generated by invoking the external skill-creator skill at implementation time (external dependency, ref: Q2); the deliverable still conforms to in-repo layout regardless of generator.
- *SKILL.md body under 500 lines / 5000 tokens* → body stays lean; overflow (full PRD template, expanded-format guidance, examples) moves to `references/` files, mirroring `qrspi-work` (ref: Q5). Verified by a `line_count('SKILL.md', 500)` eval assertion (ref: Q7).
- *Detailed reference material in references/* → `references/prd-template.md` (canonical 6-section template) and `references/expanded-format.md` (when-to-expand guidance, extra sections) (ref: Q5, ref: Q6).
- *Enforces problem-first structure* → SKILL.md procedure forbids writing Solution Overview until the Problem Statement answers all four required questions, copying the `qrspi-ticket` gating pattern (ref: Q8).
- *Default PRD template with all six core sections* → `references/prd-template.md` contains Title & Metadata, Problem Statement, Goals & Non-Goals, Solution Overview, Success Metrics, and Scope/Milestones/Open Questions.
- *SMART success metrics with baseline/target/timeframe* → template embeds the `| Metric | Baseline | Target | Timeframe | Measurement Method |` table and categorizes primary/secondary/guardrail.
- *Explicit non-goals section in every generated PRD* → template marks Non-Goals mandatory; SKILL.md instructs the agent to refuse to finalize a PRD lacking non-goals.
- *User stories use As-a/I-want/So-that with Given/When/Then* → template/reference encodes the story + acceptance-criteria format.
- *Asks clarifying questions when evidence is missing* → SKILL.md conversational gate (ref: Q8): if problem evidence is absent, ask before proceeding.
- *Supports lean one-pager AND expanded multi-section* → default = lean 6-section; `references/expanded-format.md` defines the scale-up path, mirroring the multi-mode pattern of `qrspi-work` (ref: Q9).
- *Guidance on when to expand* → explicit "expand when X" rule block in SKILL.md plus the expanded-format reference.
- A new eval case in `evals/suite.json` exercises the skill and asserts on output (problem-before-solution, non-goals present, SMART table, SKILL.md size) (ref: Q10, ref: Q12).

## Pattern Decisions

### Decision 1: Self-contained skill vs. thin-wrapper + agent

| Option | Approach | Pros | Cons |
|--------|----------|------|------|
| A | Self-contained SKILL.md (like `qrspi-ticket`) with overflow in `references/` | Matches a real in-repo precedent; no Linear/pipeline coupling; portable | Body must stay disciplined to hold the 500-line budget |
| B | Thin wrapper + `.claude/agents/writing-prds.md` (like qrspi phases) | Consistent with 8/10 skills | Agent pattern is QRSPI-pipeline-specific (ticket fetch, mode:auto, orchestrator spawn); overkill and misleading for a standalone authoring skill |

**Recommendation:** Option A
**Rationale:** The PRD skill is not a QRSPI pipeline phase and has no Linear ticket to fetch; `qrspi-ticket` is the closest precedent (a self-contained conversational authoring skill) (ref: Q8, ref: Discovered Patterns). The thin-wrapper+agent pattern exists only to serve the orchestrator (ref: Q1).
**NEW PATTERN?** No — `qrspi-ticket` and `qrspi-work` already establish self-contained skills.

### Decision 2: Where the PRD template lives

| Option | Approach | Pros | Cons |
|--------|----------|------|------|
| A | `references/prd-template.md` under the skill dir | Keeps SKILL.md under budget; loaded on demand; co-located with skill | One extra file |
| B | Inline fenced block in SKILL.md (like `qrspi-ticket`) | Single file | Full 6-section template + SMART table + story format risks the 500-line budget |
| C | `.qrspi/templates/prd.md` | Reuses the templates dir | `.qrspi/templates/` is QRSPI-pipeline-specific and "reference only — not written locally"; wrong home for a standalone skill (ref: Q6) |

**Recommendation:** Option A
**Rationale:** Lazy-loaded `references/` files are the established overflow mechanism (`qrspi-work/references/review-cascade.md`) and protect the SKILL.md size budget (ref: Q5, ref: Q7). `.qrspi/templates/` is reserved for the pipeline (ref: Q6).
**NEW PATTERN?** No.

### Decision 3: How to enforce problem-first ordering and mandatory non-goals

| Option | Approach | Pros | Cons |
|--------|----------|------|------|
| A | Imperative prose rules + self-review checkpoint in SKILL.md (the `qrspi-ticket` pattern) | Proven in-repo; no new tooling; flexible | Enforcement is model-followed, not mechanical |
| B | A script under `scripts/` that validates a generated PRD | Mechanical | No in-repo precedent for skill `scripts/`; adds maintenance; PRD lives wherever the user wants, hard to locate |

**Recommendation:** Option A, backed by eval assertions for verification
**Rationale:** `qrspi-ticket` already enforces ordering and content gates through prose rules and a self-review question, and the repo verifies behavior through evals rather than runtime scripts (ref: Q8, ref: Q10, ref: Q12). Mechanical PRD validation has no precedent and unclear file location.
**NEW PATTERN?** No.

### Decision 4: Default-vs-expanded mode encoding

| Option | Approach | Pros | Cons |
|--------|----------|------|------|
| A | Default lean path in SKILL.md + explicit "expand when X" rule block + `references/expanded-format.md` | Mirrors `qrspi-work` multi-mode dispatch; keeps body lean | Requires clear expansion triggers |
| B | Two full templates, both inline | Self-contained | Doubles body size; blows the budget |

**Recommendation:** Option A
**Rationale:** `qrspi-work` demonstrates multiple modes in one SKILL.md selected by explicit conditions; overflow detail belongs in a reference (ref: Q5, ref: Q9).
**NEW PATTERN?** No.
