## Core Principles

**Single-Commit-Per-Branch (HARD DIRECTIVE)** — Each branch in a Graphite-tracked stack must have exactly one commit. This is non-negotiable. Use `gt create` to make a branch with one commit, or `gt modify` to amend the existing commit. Never run raw `git commit` on a Graphite-tracked branch.

**Always use `--no-interactive`** — Every `gt` command must include `--no-interactive` to prevent interactive prompts from hanging the agent session. When additional flags are needed (e.g., `--no-edit` for `gt submit`), include them explicitly.

**Never use raw git on Graphite-tracked branches:**
- Forbidden: `git branch`, `git rebase`, `git commit`, `git commit --amend`, `git push`, `git merge`
- Permitted: `git add`, `git status`, `git diff`, `git diff --cached`, `git stash`
- For amendments: use `gt modify` instead of `git commit --amend`

## Staging Rule

**NEVER use the -a flag on `gt create` or `gt modify`.** This is a hard rule. Always stage changes explicitly before running a Graphite command.

Correct workflow:
1. Run `git status --short` to see what files have changed
2. Run `git add <specific-files>` to stage only intended changes
3. Run `git diff --cached` to verify the staged diff looks correct
4. Then run `gt create` or `gt modify` with the `-m` flag and commit message

## Workflow Loop

### Create a new branch with a commit

```bash
git status --short
git add <files>
git diff --cached
gt create <branch-name> --no-interactive -m "message"
gt log short --no-interactive
```

### Submit (push) the current stack

```bash
gt submit --no-edit --publish --no-interactive
```

Always ask the user for confirmation before running `gt submit`.

### Modify the current branch's commit

```bash
git status --short
git add <files>
git diff --cached
gt modify --no-interactive -m "amend message"
gt log short --no-interactive
```

### Sync with main

```bash
git status --short
gt sync --force --delete-all --no-interactive
gt log short --no-interactive
```

### Navigate the stack

Directionality: downstack = toward trunk/main, upstack = away from trunk/main.

```bash
gt bu --no-interactive       # branch up (upstack, toward tip)
gt bd --no-interactive       # branch down (downstack, toward trunk)
gt stack top --no-interactive  # show top branch without switching
gt log short --no-interactive
```

### Move a branch to restack on top of another

```bash
gt move --onto <target-branch> --no-interactive
gt log short --no-interactive
```

### Delete a branch

```bash
gt delete <branch-name> --no-interactive
```

## Safety Rules

1. **Always check `git status`** before destructive operations (`gt submit`, `gt sync --force`, `gt move`, `gt restack`).
2. **Always run `gt log short --no-interactive`** after any mutation (create, modify, move, sync) to confirm the resulting stack structure.
3. **Ask the user for confirmation** before `gt submit` — it pushes to the remote and creates/updates pull requests.
4. **Use `--no-interactive` on every `gt` command** to prevent session hangs.

## Conflict Resolution

When conflicts arise during gt restack, gt sync, or gt move, use gt continue — never git rebase --continue. See .claude/skills/using-graphite-cli/references/conflict-resolution.md for full procedures.

## Co-authorship Trailer

All commit messages must include the co-authorship trailer. Use a heredoc when passing the message via `gt create` or `gt modify`:

```bash
gt create <branch> --no-interactive -m "$(cat <<'EOF'
Short description of change

Co-Authored-By: Claude Opus 4.7 <noreply@anthropic.com>
EOF
)"
```

The trailer must be present in every commit message generated by this skill.
